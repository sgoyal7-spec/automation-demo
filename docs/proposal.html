Automation Demo Proposal

Standalone technical demo for Outbound Consulting · Prepared October 22, 2026
Recommendation in one line: build a small standalone TypeScript app (Slack + mini CRM + AI reply handling) and run it on one small EC2 host in the existing AWS account, fully separated from the Exydio stacks.

1. Goal and constraints

  • Show Outbound Consulting a live, interactive automation and let them review the code.
  • Share nothing proprietary: no Exydio database, AI agents, CRM, dialer, or shared packages.
  • Separate codebase, separate deployment, separate Slack workspace.
  • Ready by 6 AM Eastern tomorrow. Roughly 12 hours of build time.

2. What to build

Stack: Next.js, SQLite via Prisma, Slack Block Kit, Amazon Bedrock (Claude) for the AI step. Roughly 600 to 1,000 lines. Same stack family as Exydio, so the code reads like how the team works without sharing any of it.

  1. Simulated LinkedIn inbox. Click a canned prospect reply such as "Yes, send me times." Claude classifies it as interested, objection, meeting request, or not now. The app writes a lead record and posts a Slack message with a suggested reply and two action buttons.
  2. Two-way Slack. The "Book meeting" button marks the lead booked and posts a meeting prep brief back to the channel. This proves interactivity, not just a webhook.
  3. Scheduled jobs. A timer flags leads with no touch within N minutes and posts an escalation, plus a daily activity digest. N is set short for the live demo.
  4. Mini CRM page. A plain table of leads with status, owner, and interaction history ties everything together.

This covers five of the seven workflows Manny listed with a single data model.

4. Infrastructure

Serverless does not provide a static IP, so we pick one approach. For a live demo built in 12 hours, the single host is lower risk.

  • One t4g.small EC2 in us-west-2 with an Elastic IP, Docker Compose, and Caddy for automatic TLS. Under $15 per month. One SSH session to debug, no cold starts.
  • Point one of Manny's GoDaddy domains at the Elastic IP. Share the URL with the client, not the IP.
  • Instance IAM role scoped only to Bedrock InvokeModel. No VPC peering and no access to Exydio RDS, ElastiCache, or secrets.
  • Deployed by a short shell script or a tiny separate Pulumi project. Never from the Exydio Pulumi stacks or CodeBuild pipelines.
  • Serverless option for later: the same app ports to Lambda with a Function URL and DynamoDB if the client wants that story.

5. Protecting Exydio IP

  • New git repository. No imports from Exydio packages, no shared environment files or secrets.
  • Fresh free Slack workspace used only for the demo.
  • Bedrock keeps model calls inside the AWS account, so no new third-party API key to hand around.
  • Share the code as a private repo with temporary read access, or release it under MIT since nothing in it is proprietary.

7. Demo script for the call

  4. Click an objection reply. Show the different classification and suggested handling.
  5. Wait for the escalation timer to fire on an untouched lead.
